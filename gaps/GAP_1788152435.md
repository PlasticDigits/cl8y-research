## Executive summary

`cl8y-research` is a **single Rust crate** that implements a fixture-complete weekly blog pipeline and in-memory vector search so `CL8Y-web` can stay a static Vite SPA. Security guardrails (SSRF host allowlist, MDX sanitizer, create-once Replicate budget, Telegram redaction, secret-marker lint) are real and tested. The fixture happy path writes the issue’s artifact set without live tokens.

It is **not yet an operator-usable weekly worker**. `--live` only swaps the Replicate client; collection still reads `fixtures/*/sources.json`. `TELEGRAM_BOT_TOKEN`, `GITLAB_TOKEN`, and `GITHUB_TOKEN` are parsed and never used. `publish-mr.md` is copy-paste instructions, not a `glab` MR. Postgres exists in CI and `#[ignore]` locally, but `ingest` / `search` / `week` never persist to it. Canonical token addresses are a four-entry hardcoded list that does not consume `cl8y-dex-terraclassic/tokenlist`.

The highest-leverage product decision is **how a draft becomes a visitor-facing post**. Today that is a human MDX copy into `CL8Y-web` plus a marketing-site rebuild. That is the time sink. Hosting approved posts on a `cl8y-research` API (and having `CL8Y-web` fetch them) removes per-post MRs from the SPA. Until that exists, auto-opening a feature-branch MR with `glab` (merge/redeploy still human) is the minimum publish automation the issue already asked for.

**No on-chain surface** — gas optimization is out of scope. Postgres/query cost is the analog (no vector index; search scores dropped).

| Theme | Verdict |
|-------|---------|
| Fixture pipeline + invariants | Solid |
| Live collection (indexer / GitHub / GitLab / Telegram) | **Not wired** |

| Visitor blog UX / e2e | One static post; **zero** Playwright coverage of `/blog` |

## 3. Publish path — MDX MR vs posts API (decision)

This is the main product gap. Two designs are in play.

### 3.1 Today

1. Worker emits `post.mdx` + `publish-mr.md` on disk.
2. Human copies into `CL8Y-web/src/blog/posts/<slug>.mdx` and `public/images/blog/<slug>-hero.jpg`.
3. Human opens a feature-branch MR on the **marketing site**.
4. Merge rebuilds Vite, prerenders `/blog/<slug>`, regenerates `dist/rss.xml`, deploys.

Costs: every weekly recap is a frontend MR, full `yarn test && typecheck && lint && build`, prerender (Puppeteer), and review of a 2000-word MDX file in a repo whose job is positioning/headers/token directory — not journalism. Existing slugs and recent-post diversity must be hand-synced into fixtures. [CL8Y-web!4](https://gitlab.com/PlasticDigits/CL8Y-web/-/merge_requests/4) is still only a docs pointer.

`CL8Y-web` blog is compile-time:

- `import.meta.glob("./posts/*.mdx")` + `virtual:blog-post-meta` (`src/blog/blogIndex.ts`)
- Prerender routes from the posts directory (`vite.config.ts`)
- RSS from MDX frontmatter (`scripts/generate-rss.mjs`)

Runtime fetch was never designed.

### 3.2 Option A — keep static MDX, auto-open MR (`glab`)

Matches the original issue (“open a draft MR; human merges”) and the operator note: *writes `publish-mr.md` and uses `glab` to create an MR; merge and redeploy stay separately approved*.

Minimum implementation:

- After emit, copy MDX + hero into a throwaway `CL8Y-web` clone on `draft/weekly-<slug>` (never `main`).
- `glab mr create --fill --remove-source-branch=false` with `DraftMr` body (`auto_merge: false`).
- Token: `contents:write` on feature branches only.
- CI on `CL8Y-web` remains the merge gate.

This cuts copy-paste but **does not** cut SPA CI time or MDX review in the marketing repo. Still the right incremental step if SEO prerender must stay git-canonical.

### 3.3 Option B — `cl8y-research` hosts posts; `CL8Y-web` fetches (recommended medium-term)

Stores approved posts (MDX/HTML body, frontmatter, hero blob) in Postgres. Exposes a small public read API, for example:

- `GET /v1/posts` — list meta (title, slug, date, description, tags, hero URL, wordCount)
- `GET /v1/posts/:slug` — body + meta
- `GET /v1/rss.xml` — canonical feed (can replace or feed `CL8Y-web`)
- `GET /v1/images/blog/:slug-hero.jpg`

Human approval moves **into this repo** (`cl8y-research publish --slug …` or a private admin action). No per-post `CL8Y-web` content MR. Merge/redeploy of the SPA is only needed when the **fetcher UI** changes.

`CL8Y-web` stays a static SPA if it:

1. Fetches the list/post JSON at runtime (loading + empty + error states on `/blog` and `/blog/:slug`), and
2. Either **webhook-triggers a prerender-only pipeline** that snapshots the API at build time (no MDX in git), or accepts that OG/prerender for new slugs lags until the next marketing deploy.

Preserve invariants:

- Worker still does not push `CL8Y-web` `main` or auto-merge.
- Secrets stay here.
- Sanitizer/lint still run before a post becomes `published`.
- `wordCount` computed server-side at publish, not authored by the model.

**Do not** put Replicate/Telegram tokens in the Vite app to “fetch drafts.” Public API is published artifacts only.

### 3.4 Recommendation

| Horizon | Do |
|---------|----|
| Now | Option A: `glab` feature-branch MR from emit. Unblocks weekly cadence without redesigning SEO. |
| Next | Option B: publish store + public GET API + `CL8Y-web` fetch. Trigger a prerender job on publish so `/blog/:slug` and RSS stay shareable. Delete the MDX copy ritual. |

Keeping both forever (MDX in git **and** API) will drift. Pick API-as-source-of-truth once Option B ships.

## 4. Operator notes you called out

### 4.1 Live Telegram Bot API (`t.me/plasticann`, `t.me/ceramicliberty`)

**Status:** fixtures only.

`src/telegram.rs` is redaction + theme aggregation. `collect_from_fixture` filters rooms against `TELEGRAM_ROOMS`. There is no HTTP client to `api.telegram.org`.

Operator setup should be:

- Dedicated bot, member of those two rooms only (least privilege).
- `TELEGRAM_BOT_TOKEN` in env (already in `.env.example`).
- CI remains fixtures; live collect is an explicit `--live-sources` (name TBD), never default on MR pipelines.
- Retention 14 days is a constant (`TELEGRAM_RETENTION_DAYS`) with **no delete job** and no `collected_at` purge.
- Bot API uses a token, not a Telethon session. Either implement Bot API and drop “session `0600`” docs, or add a real MTProto client and chmod the session file. Mixing the two in the README is misleading.

Missing tests: live client with recorded `getUpdates` fixtures (HTTP mock), membership check that a third chat id is dropped, retention purge.

### 4.2 Worker auto-opening a `CL8Y-web` MR

**Status:** `src/publish.rs` builds an in-memory `DraftMr`; `write_publish_template` writes a markdown cheat sheet. No `glab`, no git, no push.

`gitlab_token` is loaded and unused. Issue acceptance: “A human-reviewable draft can be dropped into `src/blog/posts/`” — that drop is still manual.

Constraints to keep: feature branch only, `auto_merge: false`, `remove_source_branch: false`, MR touches only `src/blog/posts` + `public/images/blog`, secret lint on MR body. Merge and Render/deploy stay human.

### 4.3 Postgres roundtrip (Docker pgvector; CI wired; local `#[ignore]`)

**Status:** matches the note.

- Compose: `pgvector/pgvector:pg16`, user/db `cl8y`, host port **5433**.
- CI `postgres` job: service alias `postgres`, `DATABASE_URL` set, runs `cargo test --features postgres --all-targets` then `-- --ignored`.
- Local `tests/postgres.rs`: `#[ignore = "requires DATABASE_URL and pgvector"]`. Without `DATABASE_URL` it is skipped even if you pass `--ignored` (it `expect`s the var).
- Makefile has no `postgres-test` / `compose-test` target.
- `PostgresStore::search_async` does not return cosine/`<=>` distance (`score: 0.0` always). Memory search does. Agents cannot rank Postgres hits.
- No HNSW/IVFFlat index — `ORDER BY embedding <=> $1` is a sequential scan.
- Schema is duplicated: `migrations/001_init.sql` and `store::postgres::migrate` inline SQL. sqlx migrations are not used (`sqlx::query` strings, no compile-time check).
- `parse_kind` maps unknown `source_kind` to `Repo` (wrong label, and `onchain_authoritative()` becomes true for garbage).
- Week/search never call `upsert_async`. A green CI roundtrip does not mean production search is persisted.

### 4.4 Tokenlist from `cl8y-dex-terraclassic`

**Status:** not consumed.

Canonical allowlisted remotes include `github.com/PlasticDigits/cl8y-dex-terraclassic`, but collection never fetches:

## 5. Security

Strengths are real: HTTPS-only fetch helper, exact host match (no `cl8y.com.evil` suffix), private/link-local/metadata blocked, punycode rejected, userinfo rejected, explicit ports rejected, open-redirect query keys rejected, no redirect follow on indexer GET, parameterized SQL, secret-marker fail on artifacts, injection fixtures in `tests/issue_plan.rs`.

| Sev | Finding | Location |
|-----|---------|----------|
| **H** | Live collection unused, but when wired: **no DNS pinning**. Hostname allowlist can still hit a rebinding/private IP after resolve. | `allowlist.rs`, `fetch_allowlisted_json` |
| **H** | `HttpPredictor` client is built **without** `redirect(Policy::none())`. Indexer client correctly disables redirects. | `replicate.rs` vs `collect.rs` |
| **H** | Budget + `create_count` increment **before** POST. Network failure consumes budget with no prediction id → cannot `fetch`, may encourage a second create. | `HttpPredictor::create_once` |
| **H** | `poll` returns on first HTTP 200 even if `status` is `starting`/`processing`. Live `--live` can emit empty/partial output or skip waiting. | `HttpPredictor::poll` |
| **M** | IPv6 blocking is prefix-string heuristics (`fd`, `fe80:`), not a real IP parser. Unique-local/other docs ranges can slip through. | `is_blocked_ip_host` |
| **M** | Secret lint is substring markers (`REPLICATE_`, `BOT_TOKEN`, `BEGIN `). A model can leak a raw token that does not include those labels. No entropy/hex detector. `secrets::redact` exists but the pipeline **fails closed** instead of redacting — unused helper. | `secrets.rs` |
| **M** | Telegram redaction is `@handles` + address-like tokens + a tiny insult lexicon. Display names, forwarded quotes, photos, URLs in text, and team-member `from` spoofing (`is_team` is attacker-controlled in fixtures) are weak. Live Bot API must set `is_team` from chat member info, not message text. | `telegram.rs` |
| **M** | `INDEXER_HOSTS` includes `indexer.bridge.cl8y.com` while docs say that API does not exist. A bad `BRIDGE_INDEXER_BASE` would be allowlisted. | `invariants.rs`, `docs/bridge-indexer-gap.md` |
| **M** | No Gitleaks / `cargo-audit` / `cargo deny` / secret scanning in CI (legal repo has Gitleaks). `.env` gitignored; still no hook. | `.gitlab-ci.yml` |
| **L** | `tracing` is initialized in `main` and almost never used; errors go to `eprintln`. Harder to prove logs do not dump tokens. | `main.rs` |
| **L** | Session permission story is documentation-only; no `chmod 0600`. | README vs no session code |
| **L** | Future public posts API has no design for cache headers, rate limit, or “draft vs published.” Shipping Option B without that is an unauth dump of unpublished model output. | n/a |

SSRF fixture test covers `http://169.254.169.254/` via `ssrf_url` in the bundle (rejected because not HTTPS / blocked host). Good. Live `--live` path has no equivalent integration test against a mock HTTP server.

## 6. UI / UX

This crate has **no UI**. Visitor UX lives in `CL8Y-web`. Agent UX is the CLI.

### 6.1 Visitor (`CL8Y-web` `/blog`)

Shipped: list page (“Field notes from the cross-chain economy”), featured + recent cards, article layout with reading time, breadcrumbs, SEO/OG, RSS, header/footer Blog links, token/venue chrome on the article. One post: `cl8y-roadmap-cmm-bridge-yieldomega` (2026-05-10). The H1 eyebrow says **“CL8Y Research”** while nav/footer say **Blog**.

Gaps a reader would notice:

- Naming: chrome “Blog” vs page “CL8Y Research” (same surface).
- No weekly cadence — archive is a single roadmap essay.
- **No Playwright spec mentions `/blog`.** `e2e/` covers token copy, listings, chrome, discovery, trade. A broken glob or prerender of `/blog/:slug` would not fail those jobs.
- No tag filter, search, pagination, or related-posts (fine at n=1; needed if weekly posts exist).
- Missing hero file 404s (worker skip-image default).
- No subscribe CTA beyond RSS; RSS is easy to miss (no visible `/rss.xml` link in the snippets reviewed).
- `yieldomega.com` is a first-party product URL in `siteUrls.ts` but **not** in worker `POST_HREF_HOSTS` — generated posts cannot link it; sanitizer turns it into plain text.
- Same for TidalDex / PancakeSwap / CoinGecko (directory chrome can show them; post body cannot). That may be intended; it is undocumented.

### 6.2 Operator / agent CLI

- `cl8y-research week --live` looks like production and still reads fixtures.
- `--skip-image` defaults **true** (`default_value_t = true`). Enabling a hero is `--skip-image=false`, which is easy to miss. Prefer `--image` opt-in.
- `ingest` prints “in-memory” even if `DATABASE_URL` is set.
- `search` re-collects fixtures every invocation; nothing is durable.
- No `week --live-sources`, `publish --glab`, `telegram-probe`, or `tokenlist-sync` commands.
- Duplicate `cargo test` in CI/Makefile/`AGENTS.md` is a retest convention, not a UX issue, but CI time is doubled for no extra coverage.

| Replicate spend | Editor bundle = 1 create (good vs issue’s 11). Text model id is a placeholder. Image default off (good). Budget charged before HTTP (bad). |
| Postgres | No vector index; full scan `<=>`. Dim 64 hashing embedder is cheap and **weak** for retrieval quality. Live embeddings must match dim 64 or migrate. |
| CI | Double `cargo test`; clippy + fmt + fixture week + postgres. Acceptable at this size. |
| Hashing embedder | Fine for fixtures. Production search quality will disappoint; plan a real embed model with create-once, same dim or a migration. |
| Editor pass files | 11 identical copies on disk. Either real per-pass outputs or one `editor.md`. |
| `Regex::new` on every `lint_markdown` / `sanitize_body` / `redact_message` | Compile once with `OnceLock`. Not user-visible, easy win. |

## 10. DRY, readability, language/library best practices

### DRY

- `FixtureBundle` constructors copied in `collect.rs` tests, `pipeline.rs` tests, `tests/issue_plan.rs`.
- `long_body` / `sample_body` paragraph padders duplicated (and the happy-week `replicate.json` is the same paragraph ~30 times to hit 2000 words).
- SQL schema in both `migrations/001_init.sql` and `store.rs`.
- Skills copied under `.cursor/skills/` and `skills/`.
- Address lists: worker invariants, CL8Y-web `tokenDirectory.ts`, DEX `tokenlist.json` — three sources of truth.
- `search.rs` is a 14-line wrapper around `store.search`.
- `render_report` / `write_publish_template` vs unused `DraftMr` JSON.
- Dead config: `telegram_bot_token`, `gitlab_token`, `github_token`, `Config::default_repos()`, `secrets::redact`, `TELEGRAM_RETENTION_DAYS` (constant only), `SourceKind::onchain_authoritative` (never consulted by `search`).
- `migrations/001_init.sql` is not `include_str!`’d; `migrate()` re-types the DDL.

### Readability

- `pipeline.rs` (~621 lines) mixes stage machine, planning, diversity, IO, report, tests. Split `plan`, `emit`, `fs`.
- `run_with` leaking tempdirs via `mem::forget` is a test smell; use `TempDir` keep or assert before drop.
- `plan_week` `serde_json::from_str(...).unwrap_or_else` silently accepts non-JSON model output as a topic line — hard to debug live failures.
- `skip_image` inverted flag is confusing.
- `SourceKind::onchain_authoritative` includes `Repo` (READMEs are not onchain). Name vs behavior mismatch.

### Rust / library practice

- Blocking `reqwest` + optional tokio only for Postgres. Fine for a CLI; a future API should be async end-to-end (or `reqwest` rustls async).
- sqlx without `query!` macros or `sqlx::migrate!` — no compile-time SQL check, no versioned migrator.
- `Predictor: Send + Sync` but `create_once` takes `&mut self` — trait is slightly over-constrained.
- `chrono` + `uuid` used well; `serde_yaml` 0.9 is frozen/unmaintained — consider `serde_yml` or a small frontmatter writer (already custom in `emit_post`).
- No `thiserror` for HTTP status mapping; everything is `Error::Http(String)`.
- Clap `env` feature enabled; most config still manual `std::env::var` in `Config::from_env`.
- Replicate live body `{ "model", "input": { prompt, step } }` is **unverified** against current Replicate HTTP API (classic API wanted `version`; models API is `POST /v1/models/{owner}/{name}/predictions`). Treat `--live` as a prototype until a recorded cassette passes.
- Poll sleep is a tight 8 × 400ms loop — too short for real GPT-image / large text jobs.
- `wrap_untrusted` is prompt-pattern only; it does not constrain model output (sanitizer does, after the fact).
